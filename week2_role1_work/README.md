## Important assumptions

- Carrier frequency: 28 GHz.
- Transmit power: 0.5 W.
- Transmit array: 8 × 4 URA.
- Receive array: 4 × 2 URA.
- Element spacing: half wavelength.
- Antenna element: isotropic, as specified in the team's frozen v1 model. Do not mix this model with a cosine-element or patch-element table.
- Ray tracing: SBR with at most one reflection, as configured for the current scenario.
- The minimum finite path-loss ray is selected for each transmitter–receiver link.
- Fixed steering elevations: Tx = −30°, Rx = 0°.
- Large-scenario serving assignment: `S.cfg.servingTx = [1 2 3 1 2 3]`.
  - Tx1 serves Rx1 and Rx4.
  - Tx2 serves Rx2 and Rx5.
  - Tx3 serves Rx3 and Rx6.
- The code stores approximate heading metadata (clockwise from north). The beam-angle search remains the team's existing azimuth grid; it has not been silently changed to a joint azimuth/elevation search.

## Run instructions

1. Extract the project folder fully.
2. In MATLAB, set **Current Folder** to `week2_role1_work`.
3. Confirm that `berlin.osm` covers every transmitter and receiver site. The supplied map may be too narrow: Rx4 is at longitude `13.503600`, west of the previously documented lower bound `13.5038`.
4. If Rx4 is outside the loaded map, export a larger OSM region. Suggested bounds:
   - Longitude: `13.5030–13.5050`
   - Latitude: `52.5605–52.5614`

   Replace `berlin.osm` with the updated map and notify Role 2 before freezing the channel table.
5. Run the baseline diagnostic:

   ```matlab
   check_four_links
   ```

6. Build the large scenario:

   ```matlab
   S = build_scenario_3x6();
   ```

   Visually confirm that all nine sites are inside the loaded map and that the geographic environment covers the intended links.
7. Generate the 18-link report:

   ```matlab
   run_18_link_report
   ```

8. Inspect the generated CSV, MAT file, and ray figures. Check for `NO_PATH`, `INVALID_PATHLOSS`, or `UNKNOWN` entries and investigate any unexpected results.
9. Confirm the antenna-heading convention with Role 2 before using the channel table for final capacity comparisons.
10. Keep the team's tagged or frozen table versions intact. Do not overwrite a tagged table version without agreement from the team.
